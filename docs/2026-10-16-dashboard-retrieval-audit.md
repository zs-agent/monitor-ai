## 已定位并修复

| 问题 | 影响 | 修复 |
| --- | --- | --- |
| 洞察缓存先于资料变化判断，手动刷新也复用旧分类文本 | 新资料进来后仍显示旧摘要 | 按资料内容指纹、时间范围和搜索词校验缓存，强制刷新重新生成 |
| 模型不可用时把旧摘要绑定到新资料ID | 摘要与资料不一致 | 清空不匹配的旧文本，展示本次原始线索与真实状态 |

| 只把前20条标题发给模型，却声称摘要覆盖整个分类 | 覆盖数字夸大 | 区分分类资料条数、实际摘要参考条数，来源键只记录实际输入 |
| 所有历史记录放在“今日”标题下，时间窗与摘要无关 | 旧资料看起来像当日新闻 | 摘要、搜索、时间范围联动；默认显示“AI洞察”，明确范围 |
| HF论文字段变化后用抓取时间代替发表时间 | 旧论文被显示成几分钟前 | 读取嵌套publishedAt，缺失日期保留未知；RSS/GitHub/S2同样不伪造新时间 |
| 通用模型词优先，GitHub介绍中的market/research等词影响分类 | 行业、论文、实战混入不相干内容 | 新闻意图优先；仓库归产品，明确教程/资源归实战；无行业新闻则如实为空 |
| HN/HF点赞数转换为信源数量 | 伪造多源交叉信号 | 单条来源记为1，热度与来源数分开 |
| 重点关注写死最多2条 | 条目少且无配置 | 默认6条，可选3/6/10并保存本机；依据当前范围重要度与时间排序 |
| 厂商下钻词与全局搜索拼成连续句子 | 同时包含两者的资料被漏检 | 独立条件AND匹配；厂商按全部别名筛选，保留统计时间条件 |
| 分类入口保留旧标签、语言和厂商条件 | 分类看起来无资料 | 下钻重置不兼容的面板条件；增加清除入口 |
| 保存视图没有保存厂商条件，损坏的本机数据直接进入渲染 | 恢复结果不一致或崩溃 | 保存厂商/参考条件，验证结构后读取 |
| 模型目录混合历史参考、论文和动态模型，且只按ID去重 | 内容静态、重复，论文误作模型 | 动态仓库默认展示，参考单独开关和标记，按来源URL去重，通用论文不作模型 |
| 同系列不同版本名用包含关系匹配竞技场评分 | 跨版本借用评分 | 名称完整归一化比较，保留小数版本及变体；相关资料保留版本 |
| 厂商柱状图用排序后第一行作最大值 | 改排序后柱宽超出100% | 以真正最大计数作为分母 |
| 异步请求缺少完整超时与过期响应保护 | 旧请求污染新视图，加载卡住 | 覆盖响应正文的超时、取消与请求身份检查、筛选切换隔离 |
| “5/6在线”把资料可用情况说成持续联网状态 | 容易误以为只有5条资料 | 显示“5/6来源有数据”，展示最近条数、错误和更新时间；RSS未配置单独标注 |
| RSS标题前缀截断生成ID | 相同开头的不同文章碰撞 | 使用完整链接/标题的SHA256指纹 |

## 当前环境情况

HN、HF论文、HF模型、GitHub、S2已有资料。RSSHub没有配置RSSHUB_BASE_URL，因而第六个接口没有记录；不通过伪造数据或隐藏配置问题把状态改成6/6。需要实际RSSHub服务地址后才能接通RSS。

信源接口通常返回一定数量的近期/热门记录；顶部“公开模型仓库”等索引总量与本地已收录条数是两个口径。模型目录明确不随信号时间窗变化，厂商统计则在顶部信号范围内进一步按7/30日筛选。
