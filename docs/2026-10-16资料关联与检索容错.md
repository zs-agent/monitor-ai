# 2026-10-16：资料关联接通与检索容错

## 发现的工程断点
1. 研究入口在主题匹配前按全局热度截断，相关的低热度或较新资料可能被漏掉。
2. 关联问题的监测资料未直接作为研究节点的取证入口，仍完全依赖重新搜索。
3. Hugging Face仅接入论文；顶部模型目录总数未对应具体模型记录。
4. 检索错误仅记录异常类名，无法区分DNS、TLS、连接失败或限流。
5. 个别问题检索中断会让整份报告不发布，已有研究结果只能留在动作状态中。
6. 开发环境热更新留下旧轮询回调，旧抓取逻辑可能覆盖新快照。

## 本次工程修改
- signals.select_signals先按规范化主题词与Jaccard相关性排序，再比较价值、可信度和时间，之后执行数量与单源配额。词项规范化统一处理中英文混合的版本名称。
- 原文取得链路：问题的关联来源→ResearchAdapter.search_with_sources→受校验的原文抓取→研究JSON结论→审核→整合。关联元数据或搜索摘要不能代替原文；未取得正文的候选来源不交给模型作已取得的证据。
- 同一任务内已成功抓取的原文可复用于审核，保留原始获取时间与版本，不重复请求。缓存仅由成功抓取的正文填充。
- 新增Hugging Face公开模型记录接入，热门与新近更新各50，记录稳定链接、更新时间、revision、任务类型和许可证标签。元数据仍是线索，需抓取模型卡后再形成结论。顶部百万级目录数仅为覆盖统计。
- 关联、预算调度、状态图反馈、局部更新与实验记录继续由现有后端函数执行。撤销上一轮增加的“研究设计与功能入口”，不以界面宣介代替机制实现。

## 容错顺序
1. 优先本次正常在线检索。取得结果后不会为了回退而额外请求国内检索。
2. 请求失败或无结果后，自动尝试ModelScope公开OpenAPI、Gitee公开项目查询。国内返回的也是候选来源，需原文抓取和审核；不将镜像转载当作天然独立证明。
3. 已关联资料及同任务已经抓取的原文仍可用于研究与审核，注明发现新资料的范围限制。
4. 暂时性连接失败最多增加一次重试，计入检索请求；同一任务内某来源连续失败两次后暂停30秒，跳过不计为实际请求，记录断路状态。
5. 普通检索或正文不可用以retrieval_unavailable记录失败动作，保留消耗；任务降级为partial，输出已有结论及受影响问题的待核查说明。即使全部取证不可用，也输出明确“暂不能判断”的报告，不凭空生成事实。
6. 取消、模型执行异常、持久化异常和安全校验失败继续保留失败/取消隔离规则；不会发布为正常成功任务。此次没有改写旧失败记录。
7. 旧失败记录可在“查看失败与取消记录”中展开已有阶段性结论与证据链，明确提示任务未完成，仍不进入正常报告库。
